Entry Point
Platform Message
User sends message via Telegram, Discord, Slack, or Email
Each platform channel runs in its own Tokio task via ChannelManager::start_all(). Messages become InboundMessage { channel, chat_id, sender_id, content, kind } and are published to the MessageBus (mpsc channel). Session key = channel:chat_id (e.g., telegram:12345).
Coordinator
AgentLoop::process_message()
Main processing loop — session management, pipeline orchestration, event publishing
Sequence:
1. Validate message size
2. Short-circuit emoji reactions (satisfaction scoring)
3. Get/create session via SessionManager
4. Append user message to session history
5. Fire-and-forget: embed message into LanceDB (conversation recall)
6. Fire-and-forget: log to activity log
7. Call run_pipeline() → delegates to AgentRuntime
8. Save assistant response to session
9. Publish ChatTurnCompleted domain event
10. Send OutboundMessage back to platform
Step 1
Agent Selection
AgentManager matches message to one of 5 agent profiles via weighted trigger keywords
AgentManager::match_agent(message) scores each agent's triggers against the message. Longer triggers get higher weight (word count). Falls back to general if no triggers match.

Agents: general (fallback), task, finance, automation, communication
Step 2-3
Profile Activation + MCP Filtering
Set active profile into shared state; filter MCP tools to agent's allowed list
The active profile is written to Arc<RwLock<Option<Arc<AgentProfile>>>>, read by AgentContextSource during context assembly.

MCP tools are filtered per-agent: ["*"] = all servers, ["google-calendar"] = specific server only.
Step 4
Intent Classification
Two-stage analysis: zero-cost heuristics first (~70% of messages), LLM classifier for ambiguous cases
Heuristic Stage (microseconds):
• Greeting → Direct, confidence 0.95
• Short message (<20 chars) → Direct, 0.85
• Task verbs (create/add/delete) → Reactive low budget, 0.90
• Question pattern (what is/how does) → Direct, 0.90
• Complex workflows → Reactive high budget, 0.85

LLM Classifier (only if heuristics return None):
Lightweight call using classifier_model → returns IntentAnalysis { mode, confidence, needs_orchestration }

If needs_orchestration = true, agent is overridden to general with restricted tools (ask_user, memory, delegate).
Step 5-6
Confidence Check + Context Assembly
Downgrade low-confidence Reactive to Direct; assemble system prompt, memories, and history within token budget
Confidence Downgrade: If confidence < threshold → force Direct mode to save tokens.

Context Assembly (ContextEngine::assemble):
1. Build system prompt from ~11 context sources in parallel (Bootstrap, Identity, Agent, Persona, Todo, Project, Area, Productivity, etc.)
2. Retrieve memories via UnifiedMemoryService (semantic facts + conversation recall, RRF-merged)
3. Compress history to fit remaining token budget
4. SHA-256 cache (LRU, capacity 8) avoids redundant assembly

Budget priority: SystemPrompt > Tools > Memory > History
Step 7
Tool Preparation
Filter tools to agent's allowed list; inject delegation tool if needed; add CoT planning for complex requests
• filter_tools_for_profile() retains only tools in agent's tools list (empty = full access)
• ask_user is always included
• If agent has can_delegate_to + depth < 2 → inject DelegationTool
• If complexity_score ≥ 4 → prepend chain-of-thought planning prompt
Step 8 — Execution Router
Direct Mode
DirectEngine
Single LLM call, no tools
One call to provider.chat(). If the LLM unexpectedly returns tool calls (misclassification), returns EngineResult::Escalate → retried with ReactiveEngine. Tokens from the failed attempt are combined.
Reactive Mode
ReactiveEngine
ReAct loop: think → act → observe
Iterates up to max_iterations (10–30). Each cycle: LLM call → if tool calls, execute all concurrently (semaphore=10) → append results → next iteration. Hash-based duplicate tool call prevention. If max iterations hit → forced synthesis call with no tools.
Step 9-10
Validate + Record
Validate response; record cost, strategy, and interaction patterns for learning
• ResponseValidator checks response length and content
• CostTracker::record() persists token usage to SQL (per-model pricing)
• StrategyRepo records pipeline outcome
• InteractionRecorder records behavioral patterns for the learning system
• Budget alerts at 80% and 100% of monthly_budget_usd
Output
Response to User
OutboundMessage dispatched back to the originating platform channel

Reactive Engine — ReAct Loop

1
LLM Call
provider.chat_stream(messages, tools) — sends system prompt + history + tool schemas. Streams tokens via ContentChunk events.
2
Check Response
If text only → FinalResponse (done). If fabricated tool output → inject correction, retry. If tool calls → continue to step 3.
3
Dedup Check
Hash each tool call as tool_name|args_hash. Duplicates get synthetic "already called" result without re-executing.
4
Execute Tools
All tool calls run concurrently via join_all with Semaphore(10). Each has a configurable timeout. Emits ToolStart/ToolEnd events.
5
Append Results
Tool results added as Message::tool(id, name, result) to conversation history. Loop back to step 1.
↻ Repeats for up to max_iterations (10–30, based on complexity score)
Final Response

LLM returns text without tool calls. Loop ends, response sent to user.

Max Iterations

Budget exhausted. Forced synthesis call with NO tools → LLM must produce text summary.

Direct → Escalate

DirectEngine gets tool calls. Auto-escalates to ReactiveEngine. Tokens combined.

MCP Tools

MCP tools are discovered via tools/list JSON-RPC, wrapped as McpTool (implements standard Tool trait), and namespaced as mcp_{server}_{tool}. Two transports: stdio (local) and HTTP (remote). Hot reconnect supported via unregister_by_prefix() + re-registration.
