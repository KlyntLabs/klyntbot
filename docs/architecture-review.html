~436 commands × 3 sites. 35% of commands/ (2,208 of 6,246 lines) is the dispatch_dev twin. The twin reads raw snake_case JSON while the UI sends camelCase → 52 latent silent-filter bugs; 24+ commands 404 only at runtime in browser-dev.

After — one registry, two transport adapters

Two real adapters justify the seam. camelCase decoding happens once, in the registry — not per-transport.

Problem. The same logical operation is authored at three seams kept in sync by hand, and they have already drifted into 52 latent bugs.

Solution. Declare each command once in a registry; let the Tauri transport and the dev HTTP server be two thin adapters over it.

  • locality: param decoding in one place
  • leverage: one declaration, two transports
  • kills the camelCase/snake_case drift class
  • parity is structural, not a stale comment
  • interface is the test surface — test dispatch once
  • deletes ~2,200 lines of twin code
CLAUDE.md callout. The docs acknowledge “the dev server delegates identically but discards entity updates” — the duplication is known, but the sync is manual and the DEV_COMMANDS parity test the comment promises does not actually exist.

Slim the 33-field Repos object into feature bundles

Worth exploring in-process

crates/storage/src/repos/mod.rs (struct Repos · 33 pub fields)

Before — one struct owns every feature’s repos

Repos — from_pool() builds all 33

task_alarms task_recurrence task_groups scheduled_fires reforge_state approval_pattern notes sessions …25 more

A test for one query must build all 33 — so tests bypass Repos and ::new(pool) a single repo, inconsistently.

After — feature-owned bundles behind a thin aggregate

Repos — thin aggregate of bundles
TaskRepos — alarms · recurrence · groups
SchedulingRepos — scheduled_fires
CognitiveRepos — reforge_state · approval_pattern
core infra — sessions · notes · stays neutral

A test constructs the one bundle it needs. Repos stops being a feature catalogue.

Problem. Repos encodes the full feature surface into one mandatory allocation, so storage knows about task_alarms and reforge_state — a leaky seam — and every test pays for all 33.

Solution. Group repos into feature-owned bundles; let Repos become a thin aggregate so a test builds only the bundle it exercises.

  • testability: build one bundle, not 33
  • storage stops knowing feature names
  • locality: a feature’s repos travel together
  • consistent seam — no more ad-hoc ::new
  • pre-1.0: alter schema in place, cheap
  • leverage: bundles compose for callers
06

Construct AgentRuntime complete — kill the 19-Option split-phase init

Worth exploring in-process

agent/src/agent_runtime/runtime.rs (19 Option fields · set_tool_kit/set_hook_engine) · app-core/src/plugins/bash_toolkit.rs (post_init)

Before — a hazardous ordering the type system can’t see

sequenceDiagram
  participant B as builder
  participant R as AgentRuntime
  participant P as BashToolkitPlugin
  B->>R: new() — 19 fields = None
  Note over R: process_message can run
with tool_kit = None
  P->>R: post_init → set_tool_kit(..)
  P->>R: post_init → set_hook_engine(..)
  Note over R: only now complete

tool_kit/hook_engine are Mutex<Option<…>> injected after build. Tests that skip the plugin run silently without a tool kit — the test path diverges from production.

After — dependencies resolved at construction

sequenceDiagram
  participant B as builder
  participant D as RuntimeDeps
  participant R as AgentRuntime
  B->>D: assemble (tool_kit, hooks, …)
  D->>R: new(deps) — complete
  Note over R: process_message
cannot observe a None

A RuntimeDeps seam resolves wiring once; the runtime’s interface guarantees a usable runtime. “Is it wired yet?” stops being a question.

Problem. The runtime is constructed incomplete and finished by a later post_init, so the interface admits a half-built state and tests silently exercise a different shape than production.

Solution. Resolve dependencies into a RuntimeDeps at the seam and construct the runtime complete, removing the Option/Mutex split-phase.

  • interface can’t express a half-built runtime
  • test path matches production path
  • deletes set_* mutation seams
  • locality: wiring resolved in one place
  • drops two Mutex on the hot path
  • ordering hazard becomes a compile error

Also surfaced — narrower, lower-value

The ToolEvent → AgentEvent hand-maintained isomorphism Speculative

Five variants duplicated field-for-field across two enums (tools-core/src/events.rs ↔ agent/src/events.rs), bridged by an 85-line translation match whose _ => continue silently drops any new variant. Shallow translation module that will drift; the layering reason (keep tools-core off agent) is real, so the seam stays — but a macro or shared variant set could remove the field-for-field copy.

Tool channel filter reads channel where it means session_mode Speculative

Coding vs assistant tool visibility is gated through a four-hop chain — session_mode → channel string → Channel::from_name → ChannelMask — where the immutable session_mode is the real discriminator but a channel naming accident does the work. A leaky seam with no test asserting a coding session yields a different tool set than an assistant one. Folds naturally into candidate 02.

Echo worth noting: feature-productivity (18k LOC) is a second god-crate — activity-tracker, distraction, intelligence, and nudge concerns sharing a 22-field ProductivityRepos. Same shape as candidate 03; tackle 03’s pattern first, then apply it here.

Top recommendation

Start with 01 — collapse the dual command seam.

It is the most measurable and the lowest-risk: two transport adapters already exist, so the seam is justified rather than speculative (“two adapters means a real seam”). The deepening deletes ~2,200 lines of hand-synced twin code, removes an entire class of live camelCase/snake_case drift bugs, and makes parity structural instead of a stale comment — improving both locality (decode once) and AI-navigability (one place to add a command).

Highest-risk runner-up: 04 — the reforge phase pipeline. The nightly path mutates the production database with zero real test coverage; if you weight risk over effort, do this one first.
