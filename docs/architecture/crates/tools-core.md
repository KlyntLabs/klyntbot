> **Status:** 🟢 Stable
> **Subsystem:** [07 — Tools Framework](../subsystems/07-tools-framework.md)

> **One-liner:** The trait surface 60+ crates implement against — every tool change has workspace-wide blast radius

---

## TL;DR

The framework crate. Owns `Tool`, `ToolExecute`, `ToolParams`, `FeaturePackage`, `ToolRegistry`, `ApprovalClass`, `ApprovalScope`, `RoutingContext`, `ToolOutput`, `FeatureMigration`, `JobSupervisorHandle`, `ToolCallInterceptor` + `InterceptorChain`. Plus the metadata types (`ToolMetadata`, `ToolCategory`, `CostHint`, `ToolSource`), the `Searchable` trait + Reciprocal Rank Fusion (`rrf_merge`), the `Page<T>` paginator, and `ConfigPersistence` for tools that persist user config to the DB.

Every change to this crate's public surface touches every tool in the workspace. Treat as the C ABI of the tool framework — tighten with care.

## Public API surface

### `Tool` trait (the canonical surface)

```rust
#[async_trait]
pub trait Tool: Send + Sync {
    fn name(&self) -> &str;
    fn description(&self) -> &str;
    fn parameters(&self) -> Value;                                            // JSON Schema object
    async fn execute(&self, args: Value, ctx: &RoutingContext) -> Result<String>;

    // Optional methods (all have defaults)
    fn metadata(&self) -> ToolMetadata                  { ToolMetadata::default() }
    fn is_concurrency_safe(&self, _args: &Value) -> bool { false }
    fn allowed_channels(&self) -> common::ChannelMask    { common::ChannelMask::ALL }
    fn custom_timeout(&self) -> Option<Duration>         { None }
    fn approval_class(&self, _args: &Value) -> ApprovalClass { ApprovalClass::Safe }
    fn approval_scope(&self, _args: &Value) -> ApprovalScope { ApprovalScope::ToolAction }
    fn to_schema(&self) -> Value;                                             // OpenAI function-calling format
    fn validate_params(&self, params: &Value) -> Vec<String>;
}

pub type DynTool = Arc<dyn Tool>;
```

**No `ConcurrencyClass` enum.** The `bus` crate defines one (`Safe`/`Sequential`/`Exclusive`) but the `Tool` trait uses a boolean `is_concurrency_safe(args)`. The execution loop partitions tool calls into `join_all` (safe) vs sequential (unsafe).

### `ToolRegistry` API

```rust
pub struct ToolRegistry { /* opaque */ }

impl ToolRegistry {
    pub fn new() -> Self;

    // Registration
    pub fn register<T: Tool + 'static>(&mut self, t: T);
    pub fn register_dyn(&mut self, t: DynTool);
    pub fn unregister(&mut self, name: &str);
    pub fn unregister_by_prefix(&mut self, prefix: &str) -> usize;

    // Lookup
    pub fn get(&self, name: &str) -> Option<DynTool>;
    pub fn has(&self, name: &str) -> bool;
    pub fn tool_names(&self) -> Vec<String>;
    pub fn len(&self) -> usize;
    pub fn is_empty(&self) -> bool;

    // Preparation + execution
    pub fn prepare(
        &self,
        name: &str,
        args: &Value,
        ctx: &RoutingContext,
    ) -> Result<DynTool>;

    pub async fn execute(
        &self,
        name: &str,
        args: Value,
        ctx: &RoutingContext,
    ) -> Result<String>;

    // Schema (cached)
    pub fn get_definitions(&self) -> Arc<Vec<Value>>;

    // Metadata
    pub fn get_metadata(&self, name: &str) -> Option<&ToolMetadata>;
    pub fn list_meta(&self) -> Vec<&ToolMetadata>;
    pub fn by_category(&self, cat: &ToolCategory) -> Vec<DynTool>;

    // Usage tracking
    pub fn record_usage(&self, name: &str);
    pub fn top_used(&self, n: usize) -> Vec<(String, u64)>;

    // Bulk
    pub fn take_all(&mut self) -> Vec<DynTool>;
}
```

`prepare()` is the run-time validation gate — calls `tool.validate_params(args)` and returns the `DynTool` for the caller to execute. `execute()` calls `prepare()` then `tool.execute()`.

`get_definitions()` returns an `Arc<Vec<Value>>` built on first call; mutating ops invalidate the cache. The agent runtime calls this once per LLM call.

### `ApprovalClass` + `ApprovalScope`

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]

pub enum ApprovalClass { Safe, Sensitive, Destructive, Admin }

impl ApprovalClass {
    pub fn requires_prompt_on_remote(&self) -> bool {
        matches!(self, ApprovalClass::Destructive | ApprovalClass::Admin)

#[derive(Debug, Clone, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub enum ApprovalScope {
    ToolAction,
    ToolActionResource(String),    // per-resource grants (e.g. file path)
```

Both methods on `Tool` (`approval_class(&args)`, `approval_scope(&args)`) take the **args** so tools can return different classes per-call (e.g. `MemoryTool::purge` is Destructive, `MemoryTool::search` is Safe).

## Internals

### `prepare()` is the validation gate

```rust
pub fn prepare(&self, name: &str, args: &Value, ctx: &RoutingContext) -> Result<DynTool> {
    let tool = self.get(name).ok_or(ToolError::NotFound(name.into()))?;
    let errors = tool.validate_params(args);
    if !errors.is_empty() {
        return Err(ToolError::InvalidParams(errors.join("; ")).into());
    }
    Ok(tool)
}
```

Run-time validation against the JSON Schema returned by `tool.parameters()`. Schema *generation* (from `ToolParams`) is best-effort — `validate_params` is the authoritative gate.

### Per-call approval

Approval class + scope are read with the actual arguments:

```rust
// Inside the ApprovalGate (in approval crate, but coordinated with tools-core)
let class = tool.approval_class(&args);
let scope = tool.approval_scope(&args);
```

So `MemoryTool` returns:
- `record_fact` action → `Sensitive`
- `purge` action → `Destructive`
- Other actions → `Safe`

### Tool definitions cache

`get_definitions()` returns `Arc<Vec<Value>>`. Built on first call after any `register_*` invocation; cache invalidated by `unregister*`, `register`, or `register_dyn`. The agent runtime calls this once per LLM call to build the tools array.

### Concurrency partitioning

The execution loop (in `agent`) partitions tool calls into:
- **Safe** (`is_concurrency_safe → true`): collected, sent through `join_all` capped at `MAX_CONCURRENT_TOOLS = 10`
- **Unsafe** (default, `false`): executed sequentially in original order

A safe tool with unsafe args doesn't exist as a category — `is_concurrency_safe(args)` takes the args, but most tools return a constant `true` or `false`.

### `__STRUCTURED__` parsing (unused in production)

```rust
impl ToolOutput {
    pub fn parse(raw: String) -> Self {
        const PREFIX: &str = "__STRUCTURED__";
        if let Some(rest) = raw.strip_prefix(PREFIX) {
            if let Ok(parsed) = serde_json::from_str::<StructuredPayload>(rest) {
                return ToolOutput::Structured {
                    summary: parsed.summary,
                    data: parsed.data,
                };
            }
        }
        ToolOutput::Text(raw)
    }
}
```

Parser exists; no tool emits the prefix in production. Forward-compatibility seam.

### `ChannelMask` from `common`

Tools declare `allowed_channels` via `common::ChannelMask` bitfield. Variants: `ALL`, `NON_CODING`, `CODING_ONLY`, `DESKTOP_ONLY`. The agent filters the registry per-turn by the active channel.

## Workflows

### A tool call from the LLM (full path)

```
1. LLM emits {name, args}
2. ExecutionCore (agent crate):
   - registry.prepare(name, args, ctx)
     → tool found + params valid → returns DynTool
3. InterceptorChain.check(name, args, ctx)
   → Continue / Replace / Reject
4. ApprovalGate (approval crate):
   - class  = tool.approval_class(&args)
   - scope  = tool.approval_scope(&args)
   - ClassifyHooks run (last non-None wins)
   - Look up grants in approval_grants
   - If no grant: prompt via ApprovalChannel
   - Returns Allow / Deny / Cancel
5. tool.execute(args, ctx) — runs to completion
6. ToolOutput::parse(result)
   - __STRUCTURED__ → Structured { summary, data }
   - else           → Text(result)
8. Emit ToolEvent::Completed via ctx.event_tx
```

### Writing a single-action tool via `#[derive(Tool)]`

```rust
#[derive(ToolParams)]
struct MyParams {
    #[param(required)]
    query: String,
    #[param(min = 1, max = 100)]
    limit: Option<u32>,
}

#[derive(Tool)]
#[tool(
    name = "my_tool",
    description = "Search the thing",
    params = "MyParams",
    concurrency_safe = "true",
    allowed_channels = "non_coding",
    approval_class = "safe",
)]
struct MyTool { deps: Arc<MyDeps> }

#[async_trait]
impl ToolExecute for MyTool {
    type Params = MyParams;
    async fn execute(&self, params: MyParams, ctx: &RoutingContext) -> Result<String> {
        let results = self.deps.search(&params.query, params.limit.unwrap_or(10)).await?;
        Ok(serde_json::to_string(&results)?)
    }
}
```

## Extension points

### Add a new `ApprovalClass` variant

⚠️ Cross-cutting. Every gate hook (`CodingApprovalPolicy`, plugin gates, MCP server gates) must handle the new variant. `requires_prompt_on_remote()` logic needs updating. Coordinate carefully.

### Add a new `ChannelMask` variant

Edit `common::tool_channel::Channel` + `ChannelMask`. Update the agent's per-turn filter. Document in tool definitions.

### Add a `ToolCallInterceptor`

```rust
struct MyInterceptor;

#[async_trait]
impl ToolCallInterceptor for MyInterceptor {
    async fn before_call(&self, name: &str, args: &mut Value, ctx: &RoutingContext)
        -> Result<InterceptorOutcome>
    {
        if name == "bash" {
            tracing::info!(?args, "intercepted bash call");
        }
        Ok(InterceptorOutcome::Continue)
    }
}

// Wire in app-core or agent builder
let mut chain = InterceptorChain::new();
chain.add(Arc::new(MyInterceptor));
```

### Add a `ToolEvent` variant

⚠️ Cross-cutting. Update the event relay + WS bridge + UI handlers.

### Add a `ToolMetadata` field

⚠️ Cross-cutting. Update `ToolMetadata::default`, update all tools that customize metadata, update consumers (UI, MCP server bridge).

### Add a new wiring path

**Don't.** The four existing paths (FeaturePackage / agent builder / app-core init / per-subagent) cover all known needs. See [`subsystems/07-tools-framework.md`](../subsystems/07-tools-framework.md#the-four-wiring-paths).

- **`ConcurrencyClass` enum in `bus`** is not consumed by `Tool`. Either wire it up (third "Exclusive" tier?) or remove the enum.
- **`ToolOutput::Structured` is defined but never produced** in production. Decide: implement, or remove the variant.
- **`prepare()` validation is duplicated** with the LLM-side schema check. If the model produces valid args, `validate_params` is redundant; if it produces invalid args, the LLM-side check should have caught it. Acceptable today (belt + suspenders) but worth revisiting.
- **`ToolMetadata` is rarely set** by tools — most use `default()`. The UI surface for tool metadata is thin; categories + cost hints aren't visualized yet.
- **`Page<T>` is generic** but most paginated tools return `String` from `execute`. The frontend parses the JSON. Could pass `Page<T>` through directly with structured output (blocked by `ToolOutput::Structured` being unused).
- **`JobSupervisorHandle` is large** — 9 methods + 6 default-stub PTY methods. Could split into `JobSupervisor` + `PtyJobSupervisor` traits.

See [`TECH_DEBT.md`](../TECH_DEBT.md) categories #7 + #8 for specifics.
