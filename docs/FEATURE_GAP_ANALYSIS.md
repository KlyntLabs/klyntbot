## 1. Executive Summary

The Rust rewrite is approximately **70% structurally complete** — all major modules exist
with well-defined types, traits, and tests. However, several critical integration points
are **not wired together**, meaning the system cannot function end-to-end in gateway mode.

| Category | Complete | Partial | Missing |
|----------|----------|---------|---------|
| Agent Loop | 1 | 2 | 0 |
| Channels (7) | 3 | 3 | 1 |
| Providers | 3 | 0 | 0 |
| Tools (8) | 5 | 3 | 0 |
| Config | 1 | 1 | 1 |
| Session | 1 | 0 | 0 |
| Cron | 2 | 1 | 0 |
| Heartbeat | 1 | 1 | 0 |
| CLI/REPL | 1 | 1 | 0 |
| Bus | 2 | 0 | 0 |
| Utils | 2 | 0 | 0 |

**Key blockers** (must fix before `klyntbot serve` works):
1. Tool context not wired — MessageTool/SpawnTool/CronTool have `None` references
2. Discord IDENTIFY never sent — gateway connection dies immediately
3. Subagent system has no tool access — Python gives subagents 6 tools + 15-iteration loop

## 2. Critical Gaps (P0 — Blocking)

### 2.1 Agent Loop: Tool Context Wiring

**File:** `src/agent/agent_loop.rs:478` (`update_tool_contexts`)

**Status:** `[PARTIAL]` — method exists but is an empty no-op.

**Python behavior** (`agent/loop.py:166-176`):
```python
message_tool = self.tools.get("message")
if isinstance(message_tool, MessageTool):
    message_tool.set_context(msg.channel, msg.chat_id)

spawn_tool = self.tools.get("spawn")
if isinstance(spawn_tool, SpawnTool):
    spawn_tool.set_context(msg.channel, msg.chat_id)

cron_tool = self.tools.get("cron")
if isinstance(cron_tool, CronTool):
    cron_tool.set_context(msg.channel, msg.chat_id)
```

**Impact:** Without this, the `message`, `spawn`, and `cron` tools cannot target the
correct channel/chat. The LLM will call these tools and they will fail silently or
route to the wrong destination.

**Root cause:** In `agent_loop.rs:_register_default_tools()`:
- `SpawnTool` is registered with `subagent_manager: None`
- `CronTool` is registered with `cron_service: None`
- `MessageTool` has `set_context()` but `update_tool_contexts()` never calls it

**Fix:** Implement `update_tool_contexts()` to downcast tools from the registry and
call `set_context()`. Also, pass actual `SubagentManager` and `CronService` references
when registering tools (requires `Arc` wrapping or similar).

### 2.2 Discord Channel: IDENTIFY Never Sent

**File:** `src/channels/discord.rs:174-177`

**Status:** `[PARTIAL]` — `send_identify()` is a stub that returns `Ok(())`.

**Python behavior** (`channels/discord.py:148-165`):
```python
identify = {
    "op": 2,
    "d": {
        "token": self.config.token,
        "intents": self.config.intents,
        "properties": {"os": "nanobot", "browser": "nanobot", "device": "nanobot"},
    },
}
await self._ws.send(json.dumps(identify))
```

**Impact:** The Discord gateway connection will never authenticate. After the HELLO
opcode, the server expects an IDENTIFY within a few seconds or it disconnects.

**Additional Discord issue:** The heartbeat task takes ownership of the `write` half of
the WebSocket (`gateway_loop` line 74), so there's no way to send the IDENTIFY payload
from `handle_gateway_event`. The Python version uses `websockets.connect()` context
manager which shares the connection.

**Fix:** Restructure the gateway loop to use a shared write channel (`Arc<Mutex<SplitSink>>`)
or use a command channel pattern where both heartbeat and event handler can send frames.

### 2.3 Subagent System: No Tool Access

**File:** `src/agent/subagent.rs:98-131`

**Status:** `[PARTIAL]` — Subagents spawn and call the LLM, but with zero tool access.

**Python behavior** (`agent/subagent.py:99-111`):
```python
tools = ToolRegistry()
tools.register(ReadFileTool(allowed_dir=allowed_dir))
tools.register(WriteFileTool(allowed_dir=allowed_dir))
tools.register(ListDirTool(allowed_dir=allowed_dir))
tools.register(ExecTool(working_dir=str(self.workspace), ...))
tools.register(WebSearchTool(api_key=self.brave_api_key))
tools.register(WebFetchTool())
```

**Python subagent loop:** 15-iteration agent loop with tool calls, same as main agent
but without `message` and `spawn` tools.

**Rust subagent loop:** Single LLM call with no tools — just `provider.chat(&messages, None, ...)`.

**Impact:** Subagents are severely limited. They can't read files, run commands, or
search the web. The `spawn` tool is effectively useless since the subagent can only
generate a text completion.

**Fix:** Build a tool registry for the subagent (same as Python: read_file, write_file,
list_dir, exec, web_search, web_fetch), then run an agent loop with up to 15 iterations.

---

### 2.4 SpawnTool / CronTool: None References

**File:** `src/agent/agent_loop.rs` (tool registration section)

**Status:** `[PARTIAL]` — Tools are registered but with `None` for their service references.

```rust
// SpawnTool registered with subagent_manager: None
tools.register(Box::new(SpawnTool::new(None)));

// CronTool registered with cron_service: None
tools.register(Box::new(CronTool::new(None)));
```

**Impact:** When the LLM calls `spawn` or `cron`, the tools will fail because they
check `if let Some(manager) = &self.subagent_manager` which evaluates to `None`.

**Fix:** Create `SubagentManager` and pass it to `SpawnTool::new(Some(manager))`.
Similarly for `CronService` → `CronTool`. Requires these services to be `Arc`-wrapped
for shared ownership.

## 3. Major Gaps (P1 — Core Functionality)

### 3.1 Telegram Channel: Incomplete Integration

**File:** `src/channels/telegram.rs`

| Feature | Status | Notes |
|---------|--------|-------|
| Long polling | `[COMPLETE]` | Manual HTTP polling implemented |
| /start command | `[COMPLETE]` | Sends welcome message |
| /reset command | `[PARTIAL]` | Acknowledges but doesn't clear session |
| /help command | `[COMPLETE]` | Lists commands |
| Media download | `[COMPLETE]` | Photo, voice, audio, document |
| Voice transcription | `[COMPLETE]` | Groq Whisper integration |
| Markdown→HTML | `[COMPLETE]` | Custom converter |
| Typing indicator | `[PARTIAL]` | Single-shot, not continuous loop |
| Proxy support | `[MISSING]` | Python: `builder.proxy(config.proxy)` |
| HTML fallback on error | `[MISSING]` | Python falls back to plain text |

**`/reset` gap:** Python (`telegram.py:229-248`) clears the session via
`session.clear()` and `session_manager.save(session)`. Rust just replies "History cleared"
without accessing the session manager. The Rust `TelegramChannel` doesn't hold a reference
to `SessionManager`.

**Typing indicator gap:** Python (`telegram.py:378-387`) runs a continuous loop that
sends `typing` action every 4 seconds until the response is ready. Rust sends a single
typing action when a message arrives but doesn't maintain it.

### 3.5 Heartbeat: Callback Not Wired

**File:** `src/heartbeat/service.rs`

**Status:** `[PARTIAL]` — Service is complete, but `set_callback()` is never called
from `main.rs`. The heartbeat runs but does nothing when it ticks.

**Python behavior:** The heartbeat callback invokes the agent loop's `process_direct()`
to process the HEARTBEAT.md contents.

**Fix:** In `handle_serve()` in `main.rs`, call `heartbeat.set_callback(...)` with a
closure that invokes the agent loop.
