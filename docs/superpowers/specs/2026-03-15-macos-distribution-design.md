# macOS Distribution Design

## Overview

Distribute Klynt as a macOS `.dmg` with auto-updates for beta testers, scaling to public release later.

## Repositories

| Repo | Visibility | Purpose |
|------|-----------|---------|
| `KlyntLabs/klyntbot` | Private | Source code, CI/CD workflow |
| `KlyntLabs/klynt-bot` | Public | Release artifacts + `latest.json` for updater |

## Components

### 1. Unified Binary

The desktop Tauri binary gains CLI subcommand support. When invoked with `mcp serve --stdio`, it runs the MCP server (no GUI). Otherwise, it launches the normal Tauri desktop app.

```
Klynt                          # launches GUI (default)
Klynt mcp serve --stdio        # runs MCP server over stdin/stdout
```

**Implementation:**
- Add `clap` to `crates/desktop/Cargo.toml` for CLI arg parsing
- In `main.rs`, parse args **before** constructing `tauri::Builder` — the Tauri runtime is never initialized in MCP mode
- Remove `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]` attribute — on macOS it has no runtime effect, but it would suppress stdout/stderr if cross-compiled, breaking MCP stdio
- If `mcp serve --stdio` subcommand detected: initialize `AppCore` with `AppMode::Server` (matching `klyntbot-server`'s init path, not the Desktop path), run MCP server loop, exit
- If no subcommand: proceed with normal Tauri setup

**MCP config for testers after install:**
```json
{
  "mcpServers": {
    "klyntbot": {
      "command": "/Applications/Klynt.app/Contents/MacOS/Klynt",
      "args": ["mcp", "serve", "--stdio"]
    }
  }
}
```

### 2. Auto-Updates (Tauri Updater)

Tauri's updater plugin checks a JSON endpoint on app launch.

**Update flow:**
1. App launches, checks `https://github.com/KlyntLabs/klynt-bot/releases/latest/download/latest.json`
2. Compares current version against JSON `version` field
3. If newer: shows dialog asking user to update ("Update Now" / "Later")
4. Downloads `.tar.gz` update artifact, verifies Ed25519 signature, applies it
5. Restarts the app

**`latest.json` format** (generated by `cargo tauri build`):
```json
{
  "version": "0.2.0",
  "notes": "Bug fixes and improvements",
  "pub_date": "2026-03-15T00:00:00Z",
  "platforms": {
    "darwin-aarch64": {
      "url": "https://github.com/KlyntLabs/klynt-bot/releases/download/v0.2.0/Klynt.app.tar.gz",
      "signature": "<Ed25519 signature>"
    }
  }
}
```

**Setup:**
- Add `tauri-plugin-updater` to `crates/desktop/Cargo.toml`
- Generate Ed25519 keypair: `cargo tauri signer generate -w` (the `-w` flag writes to file; without it the key prints to stdout and must be captured immediately)
- Store private key as GitHub Actions secret (`TAURI_SIGNING_PRIVATE_KEY`), passphrase as `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` (must match exactly what was entered during generation)
- Add public key to `tauri.conf.json` under `plugins.updater.pubkey`
- Configure updater endpoint in `tauri.conf.json`:
  ```json
  {
    "plugins": {
      "updater": {
        "endpoints": [
          "https://github.com/KlyntLabs/klynt-bot/releases/latest/download/latest.json"
        ],
        "pubkey": "<public key>"
      }
    }
  }
  ```
- Add update check on app startup with dialog prompt — use `tauri_plugin_updater::UpdaterExt` to check, then show a Tauri dialog with "Update Now" / "Later" buttons. If accepted, download + install + restart.

**Important:** Always publish releases as full releases (not pre-releases) on `klynt-bot`, since `/releases/latest` skips pre-releases. If a pre-release is published, the updater endpoint will 404 or return an older version.

**Security:** Ed25519 keypair (separate from Apple code signing). Private key in CI secrets, public key compiled into app. Updates rejected if signature doesn't match.

### 3. Code Signing

**Beta (now):** Skipped. Testers bypass Gatekeeper via right-click → Open. On macOS Sequoia (15+), if right-click → Open doesn't work, testers may need to run `xattr -d com.apple.quarantine /Applications/Klynt.app` after dragging to Applications.

**Public launch (future):** Apple Developer ID ($99/year) + notarization. Tauri supports this via `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_ID`, `APPLE_PASSWORD` environment variables in CI.

### 4. GitHub Actions CI/CD

**Workflow file:** `.github/workflows/release.yml`

**Trigger:** Push a git tag matching `v*` (e.g., `v0.1.0`)

**Steps:**
1. Checkout source from `KlyntLabs/klyntbot`
2. Install dependencies: Rust latest stable (MSRV 1.75 enforced by `rust-version` in `Cargo.toml`), Bun, Tauri CLI (`cargo-tauri`)
3. Run tests: `cargo nextest run --workspace` + `cargo clippy --workspace --all-targets --all-features`
4. Build: `cargo tauri build` with `TAURI_SIGNING_PRIVATE_KEY` env var set — produces `.dmg`, `.app.tar.gz` (auto-signed by Tauri), and `latest.json`
5. Create GitHub Release on `KlyntLabs/klynt-bot` using a PAT (`RELEASE_REPO_TOKEN`)
   - Tag: matches the source tag (e.g., `v0.1.0`)
   - Artifacts: `.dmg` (manual download), `.app.tar.gz` + `latest.json` (updater)

**Note:** Tauri auto-signs the `.tar.gz` updater artifact during `cargo tauri build` when `TAURI_SIGNING_PRIVATE_KEY` is in the environment. No separate signing step needed.

**Platform scope:** macOS ARM only (aarch64). Intel Mac (`darwin-x86_64`) is out of scope for beta. If a beta tester has an Intel Mac, a second build matrix leg would be needed.

**Required GitHub secrets on `KlyntLabs/klyntbot`:**
- `TAURI_SIGNING_PRIVATE_KEY` — Ed25519 private key for updater signatures
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` — passphrase for the key (if set)
- `RELEASE_REPO_TOKEN` — PAT or deploy key with write access to `KlyntLabs/klynt-bot` releases

### 5. Release Workflow

```bash
# 1. Bump version in three files (must stay in sync):
#    - Cargo.toml (workspace.package.version) — inherited by all crates
#    - crates/desktop/tauri.conf.json (version) — NOT auto-inherited, must be updated manually
#    - desktop-ui/package.json (version)
# 2. Commit
git add -A && git commit -m "chore: bump version to 0.2.0"
# 3. Tag and push
git tag v0.2.0
git push origin main --tags
# → GitHub Actions builds and publishes release to klynt-bot
```

**Note:** Tags should be pushed from `main` (merge dev → main first). The CI workflow should not restrict to specific branches, but tagging from `main` ensures only release-ready code is published.

## What's Deferred to Public Launch

- Apple code signing + notarization
- Homebrew Cask formula (`brew install --cask klyntlabs/tap/klynt`)
- Windows / Linux builds
- Changelog automation
- Version bump scripting

## Architecture Diagram

```
Developer pushes tag v0.X.0 to KlyntLabs/klyntbot (private)
    │
    ▼
GitHub Actions (release.yml)
    ├─ cargo nextest run + clippy (gate)
    ├─ cargo tauri build
    │   ├─ Klynt.dmg          (manual install)
    │   ├─ Klynt.app.tar.gz   (updater artifact)
    │   └─ latest.json        (updater manifest)
    ├─ (Tauri auto-signs .tar.gz via TAURI_SIGNING_PRIVATE_KEY)
    └─ gh release create on KlyntLabs/klynt-bot (public)
         │
         ▼
Beta testers
    ├─ First install: download .dmg from klynt-bot releases
    ├─ Updates: app checks latest.json → dialog → auto-update
    └─ MCP: /Applications/Klynt.app/Contents/MacOS/Klynt mcp serve --stdio
```
