Problem

The orchestrator is a pass-through. Deleting it would move 3,400 lines of interface surface into one file. Each section hook is shallow — its interface nearly matches its implementation.

Solution

Replace the orchestrator and section hooks with a single Zustand (or context) store. Sections read settings and dispatch updates directly. Async operations (doctor, update) become thunks on the store.

Wins

  • Delete 10 shallow section hooks
  • locality: settings logic in one module
  • leverage: one interface, N sections
  • Tests hit a store, not 50 props

One deep module. Adapters sit at the seam, not inside.

Problem

Thread state lives across a hand-rolled reducer (5 slices), a Zustand store, a legacy class (`ChatStreamStore`, 1152 lines), and a global mutable module (`threadEvents.ts`). Understanding one thread concept requires bouncing between four modules.

Solution

Fold the 5 reducer slices and the Zustand wrapper into one deep `ThreadState` module. Move the legacy v1 bridge behind an adapter at the seam. Evict `threadEvents.ts` global mutable state — its ring-buffer logic belongs inside `ThreadState`.

Wins

  • locality: thread bugs in one place
  • One seam, two adapters (Tauri, browser)
  • Delete 3 shallow wrappers
  • Tests exercise one interface

Problem

`createEventHub` is deep, but every exported `subscribeX` is a shallow pass-through. The module's interface is 30× wider than it needs to be. Adding a new event requires copy-pasting 6 lines.

Solution

Export `eventHubFor(eventName)` instead of 30 named subscribers. Callers write `eventHubFor("terminal-output").subscribe(handler)`. Type safety via a registry map or discriminated union.

Wins

  • Delete ~28 shallow wrappers
  • leverage: one interface, all events
  • New events need 1 line, not 6
  • Tests mock one factory
Also noted: services/tauri.ts is a 4-line re-export shim. Delete it and migrate imports to @/api.

Problem

`MainApp.tsx` functions as an implicit dependency-injection container and god component. It couples layout orchestration, bootstrap, global shortcuts, and feature mounting in one place. Changing any surface requires touching MainApp.

Solution

Split into `AppShell` (providers + layout frame) and `XxxSurface` modules for each major area. Surfaces register themselves or are declared in a flat route map. Bootstrap logic moves to a `useAppBootstrap` hook consumed only by the shell.

Wins

  • locality: surface changes stay in surface
  • Tests mount one surface, not MainApp
  • Delete alias hooks (useAppBootstrapOrchestration)

Adapters: TauriRpc, InMemoryFake

4 entry points. All orchestration (turn IDs, error handling, debug logging) hidden inside.

Problem

`useThreadMessaging` is 896 lines and takes 30+ parameters. It returns 25+ functions. The interface is as complex as the implementation — shallow. Every test must construct the full options object or mock the hook entirely.

Solution

Extract a plain `ThreadMessaging` module with a small interface: `send`, `interrupt`, `review`, `fork`. It owns turn lifecycle, error handling, and debug logging internally. The React hook becomes a thin adapter that reads workspace/thread context from the store and delegates to the module.

Wins

  • leverage: 4 methods, all messaging
  • locality: protocol logic in one place
  • In-memory adapter enables fast tests
  • Hook shrinks to ~60 lines
