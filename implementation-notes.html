Implementation Notes — Reforge Pipeline Testability

Running record of design decisions, deviations, tradeoffs, and open questions while executing docs/superpowers/plans/2026-05-27-reforge-pipeline-testability.md.

Pre-Execution Review Findings

Deviation (pre-emptive): ReforgeCollected did not derive Default in types.rs, but the plan assumed it did (Task 3 seed helper). Added #[derive(Default)] to ReforgeCollected — safe, behavior-neutral change for an internal collection struct.
Deviation (pre-emptive): ReviewOutput did not derive Default in types.rs. The plan's smoke test uses ReviewOutput::default(). Added #[derive(Default)] to ReviewOutput.
Design decision: EpisodicMemoryRepo query method is list_by_domain(domain, limit) (not recent_by_domain as in the plan's Task 5 draft). Used the actual method name.

Task 1 — ReforgeContextBuilder

Executed as spec'd. Builder implemented with 8 required args + 14 optional chained setters. Production call site in cron.rs migrated cleanly. app-core builds without errors.

Task 2 — Test Harness

Deviation: common::KlyntbotError::Internal does not exist. Used common::KlyntbotError::Storage("...".into()) instead in FakeReforgeHandler error paths. Any error variant works for the tests; Storage is a generic catch-all.
Deviation: The plan placed pipeline_tests.rs at src/pipeline_tests.rs, but Rust's module system for src/pipeline.rs expects submodules in src/pipeline/. Created crates/cognitive-reforge/src/pipeline/pipeline_tests.rs instead.

Task 5 — Apply + Collect

Deviation: The plan's collect_yields_none_on_empty_db test did not account for bootstrap mode. CollectPhase treats last_run_at = None as bootstrap and returns Some even on an empty DB. Set run.last_run_at = Some(jiff::Timestamp::now().to_string()) in the test to trigger the empty-db skip gate.

Task 6 — Full Pipeline

Deviation: The plan's run_reforge_returns_none_when_no_new_data test would fail on a fresh DB because bootstrap mode returns Some. Pre-seeded a previous run via h.reforge_state.record_run("{}").await so last_run_at is non-null, causing Collect to properly skip.
Deviation: The plan's seed_collectable helper was underspecified. Implemented it by inserting a dummy sessions row (required FK) and calling session_memory.upsert. Used self.fact_repo.pool() for the raw SQL insert because SessionMemoryRepo does not expose its pool.
Tradeoff: SessionMemoryRepo stores updated_at as INTEGER (epoch ms) while list_since binds an RFC 3339 TEXT timestamp. SQLite coercion means the comparison behaves differently than intended, but the existing production code relies on this behavior. The test harness works with it without modification.

Task 7 — Final Verification

Results:
  • cargo nextest run -p cognitive-reforge — 37/37 passed
  • cargo nextest run -p cognitive — 26/26 passed
  • cargo build --workspace — clean
  • cargo clippy -p cognitive-reforge -p app-core — no new warnings (all pre-existing)
  • cargo machete — no orphaned deps in cognitive facade

Open Questions

SQLite type mismatch in session_memory.list_since: updated_at is INTEGER (epoch ms) but the query binds a TEXT RFC 3339 since parameter. Should this be normalized? It hasn't caused visible issues, but it's a latent bug if SQLite coercion rules ever change behavior.
